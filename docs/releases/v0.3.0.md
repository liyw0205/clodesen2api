# v0.3.0

- Add managed client keys with hash-only secrets, rotation, expiration, network/model restrictions, RPM, concurrency and daily/monthly quotas.
- Separate administration sessions from inference keys and add versioned management writes.
- Add public model aliases, capability policies and persistent account/model 429 cooldowns.
- Add bounded asynchronous request audit, per-key filtering and storage health.
- Persist control data, settings overrides, jobs and shared admission state in SQLite; import legacy repositories once and preserve originals.
- Add bounded background jobs, progress/cancel/retry, single-flight refresh and partial cache status.
- Add consistent WAL backups, archive validation, instance exclusion, drain/restart restoration and failure rollback.
- Add verified-usage reservations, JSON/SSE settlement and reconciliation. Unverified models reject token/credit-limited calls; uncertain usage retains its reservation. Metered calls permit one upstream attempt.
- Use `VERSION` for local and CI builds and publish the five supported platform packages after Go, race and browser checks.

Upgrading imports legacy files into `data/control.sqlite3`. Keep `data/` intact.
Backups include upstream credentials and administration tokens. Restore accepts
the current schema and preserves data-directory locations. A rollback restores
the original files if replacement fails. Upstream-specific usage contracts need
operator verification before enabling hard token or credit limits.
Unknown usage stays reserved. The supported parser expects one final integer
usage object; other billing formats require protocol adaptation. Coordination
is for processes sharing one local database. Unix restore/restart is covered by
an integration test; Windows has only been cross-built. File replacement
failures roll back automatically; subsequent startup failures need operator
recovery from the pre-restore backup. Main commits test/package, and matching
version tags publish releases without overwriting existing assets.
