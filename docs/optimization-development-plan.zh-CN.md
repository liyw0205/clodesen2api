# 控制台优化开发计划

依据本轮项目审查方案开发，保留 Go、SQLite 和内嵌原生 JavaScript 技术栈。
本文件按完整范围跟踪实施，不将已完成的小批次等同于整个方案完成。

2. F2 批量操作、F4、N2、N3、B2、B3。
3. B1、N4、F5、B4、B5。
4. N5、B6、N6、B7、其余 F6 拆分和全量验收。

## 约束与回退

- 默认不自动提交或发布；版本交付按用户明确指令执行。验收不连接真实通知接收方。
- 不修改现有生产数据；数据库变更在测试副本验证，沿用升级前快照和事务迁移。
- 不增加前端框架。新模块沿用两空格、双引号、DOM textContent 和现有 CSS 变量。
- 外部请求有超时和取消；退出清理密钥、会话内数据及迟到响应。
- 任务使用已有去重和持久化语义；不自动重试结果不确定的兑换或推理。
- 列表选择范围显式展示；错误保留可操作反馈，局部失败不丢弃成功结果。
- 性能结论仅依据固定数据集的实际基准，累计统计与窗口统计分别标明口径。
- 新通知默认关闭，只通过本地模拟接收器验证，启用与真实发送由用户配置。

各批次已实现并完成当前范围验收。`internal/admin/api.go` 从 1,065 行拆为 113 行路由分派，
模型目录、积分 API/统计、账号状态、设置、准入和兑换实现分属独立文件；
`internal/server/web/app.js` 从 1,495 行拆为约 487 行，账号、请求审计、统计展示和设置
分别由 `accounts.js`、`request-records.js`、`analytics-view.js`、`settings.js` 管理，
请求沿用统一超时、取消和会话失效处理。设置冲突读取最新配置并保留本地修改，等待显式再次保存；
审计弹窗关闭/退出清理提示词与错误内容，迟到响应不能回填已退出的会话。

SQL 报表指标独立保留 31 天；采集起点之前的历史在面板明确显示为不完整。积分仅展示近 7 天本地估算，
旧数据缺乏密钥归属时不做虚构分摊。

5 万条明细分页基准（Android ARM64，当前版本 3 次）：61.4、61.9、117.9 ms；中位数
61.9 ms，约 69.5 KB、848 次分配。此前基准为 575.9 ms、232.4 MB 分配；仅用于相同固定
测试数据集的对比，不视为设备上的稳定延迟保证。新报表指标写入路径增加独立持久化；
本次只复测列表查询，未据此推断报表写入性能。

schema 3 增加紧凑指标及采集起点；不把升级前明细假作完整历史；保留 schema 2 备份恢复兼容和迁移前快照。
告警仅用本地 HTTP 接收器验证；页面和预览默认关闭，不连接真实接收方。
