# codebuddy2api 借鉴与实施方案

核对日期：2026-11-07。参考版本：[codebuddy2api v1.5.4，58fc829](https://github.com/maiphucgiang/codebuddy2api/tree/58fc829d701150b8d323875cb1a7a3d5eab8d710)。已通过远端 HEAD 核对该提交。

本文基于双方源码整理，并记录 v0.3.0 的适配实现和验收边界。开发基线为 `84394f5`（v0.2.23）；下列核心能力已在本次源码中实现，提交、远端 CI 和发行状态以 [control-plane-implementation.md](control-plane-implementation.md) 的交付门禁为准。参考与依赖许可见根目录 `THIRD_PARTY_NOTICES.md`。

## 1. 总体建议

保留 Go 后端、`net/http`、嵌入式 HTML/CSS/JavaScript 和现有账号/积分/图像转发流程，借鉴参考项目的领域边界、接口契约、交互状态和验证方式。

优先将密钥管理做成完整的请求准入与审计链路，再统一模型权限、资源限制、后台任务和控制数据持久化。配额、跨进程共享计数、任务取消与恢复是本项目的扩展设计，不能仅凭参考项目存在相近模块就视为已经解决。

| 优先级 | 目标 | 后端落点 | 前端落点 | 当前状态 |
| --- | --- | --- | --- | --- |
| P0 | 密钥生命周期与基础限制 | `internal/apikey`、`internal/admin/keys.go`、推理入口 | 密钥列表、编辑、一次展示、冲突处理 | 生命周期、清除限制、管理认证与浏览器边界测试通过 |
| P1 | 统一身份与可靠审计 | 请求上下文、审计事件、异步写入与健康状态 | 按 key 筛选、拒绝原因、审计异常状态 | 原子导入、owner恢复、脱敏、共享查询、保留期边界和升级前快照已验证 |
| P2 | 统一模型策略与冷却 | 模型目录、别名、可见性、账号/模型冷却 | 模型策略编辑、有效权限、恢复时间 | 多级映射、全链能力、禁用及冷却隔离通过回归 |
| P3 | 容量、配额、任务与缓存状态 | 准入租约、配额预留、作业状态机、刷新合并 | 用量/并发、任务进度、缓存状态 | 请求及条件式Token/积分配额、未知结算/对账、续租、作业和部分缓存已接入 |

### 1.2 跨语言适配原则

| 参考实现机制 | 本项目实现方式 | 必须保留的行为 |
| --- | --- | --- |
| FastAPI/Pydantic 参数模型 | `net/http` 路由、Go DTO、显式校验 | 字段缺省/null/空数组、数值边界、稳定错误码 |
| ContextVar 请求身份/策略 | `context.Context` 的 Principal 和策略快照 | 单请求固定 revision；取消传递；身份不因重试改变 |
| Python 锁、线程池和队列 | 短临界区、受控 goroutine、有限 channel | 并发上限、背压、关闭等待；不能每次点击无限启动 goroutine |
| React hook/resource 状态 | 独立 JS 模块及统一请求封装 | loading/empty/error/stale/conflict、请求取消、generation 防迟到响应 |
| Python SQLite 控制仓储 | `database/sql`、纯 Go SQLite 驱动和领域仓储 | 事务、CAS、迁移、忙等待上限和持久化失败反馈 |
| React 抽屉和组件 | 复用当前 dialog/表格/移动条目及 CSS | 状态生命周期、焦点与错误反馈；无需为参考代码更换框架 |

## 2. 参考实现到本项目的对应关系

| 参考项目 | 值得借鉴的实现思路 | 本项目的适配方式 |
| --- | --- | --- |
| `app/api_keys.py`、`web/src/pages/Keys.tsx` | 独立密钥实体、限制编辑、版本冲突、轮换 | Go 类型/存储负责约束；静态 JS 独立模块负责列表和表单 |
| `app/inference_auth.py`、`app/request_context.py` | 读取请求体前鉴权，请求身份与上游尝试身份分离 | `context.Context` 保存 Principal；根 request ID 贯穿日志，attempt ID 区分重试 |
| `app/model_policy.py`、`app/model_catalog_view.py`、`web/src/pages/Models.tsx` | 同一份策略控制列表展示、请求授权和上游映射 | 请求取得不可变策略快照；模型列表与转发共用决策函数 |
| `app/credential_cooldowns.py` | 账号级与模型级冷却分离，截止时间有上限，落盘失败可观察 | 扩展现有账号冷却，不将某模型的 429 扩散为整个账号停用 |
| `app/inbound_limits.py`、`app/inference_resources.py` | 提前拒绝过载，租约覆盖完整响应，取消时释放资源 | Go 准入器、幂等 `Release`、`defer` 与上下文取消；复用受控 HTTP 客户端 |
| `app/background_jobs.py`、`web/src/jobs.tsx` | 作业与触发请求分离，重复触发去重，页面重新加载后查询进度 | 有界工作池与作业 API；JS 轮询按 job ID 恢复展示 |
| `app/audit_store.py`、`web/src/pages/Logs.tsx` | 元数据审计、保留期/容量上限、聚合独立、降级可观察 | 有界写队列、批量入库、聚合表；避免每次完成请求重写完整 JSON |
| `app/control_store.py`、`app/settings.py`、`web/src/pages/Settings.tsx` | 带 revision 的写入，区分生效值/存储值/来源/锁定 | `database/sql` 事务和条件更新；配置 API 返回来源及热更新模式 |
| `app/backups.py`、`web/src/pages/Storage.tsx` | 在线一致性备份、清单、更新前备份、定时保留 | Go 备份服务；扩展覆盖本项目实际使用的账号与配置文件 |

不要机械复制以下行为：

- 参考项目标准 key 保存明文并提供 `/reveal`。本项目保留 SHA-256 摘要存储，仅创建/轮换时返回一次明文；丢失后轮换。
- 参考项目的 `JobBoard` 本身保存在进程内。可查询进度不等于重启恢复；持久化与恢复需要单独实现。
- 参考项目的多协议适配器、产品专属成长任务、OAuth/ACP 等依赖其上游能力。没有本项目上游协议验证前，不纳入直接移植。
- React hooks、Pydantic 和 Python 线程池不能原样翻译。借鉴状态生命周期，分别使用 JS 状态模块、Go 校验和受控 goroutine。

## 3. P0：将 key 从通行凭证变成可管理身份

### 后端

密钥公开字段沿用当前工作树契约：`id/name/prefix/enabled/expiresAt/ipAllow/rpm/models/createdAt/lastUsedAt/version`。原始 secret 不进入列表、请求记录、日志或备份清单，存储只包含摘要。

现有管理接口保留：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /admin/api/keys` | 列表、24 小时请求汇总，以及外部兼容 key/匿名模式是否启用 |
| `POST /admin/api/keys` | 创建并返回一次 secret |
| `PUT /admin/api/keys/{id}` | 携带 version 更新，旧版本返回 409 |
| `DELETE /admin/api/keys/{id}` | 携带 version 删除 |
| `POST /admin/api/keys/{id}/rotate` | 携带 version 轮换，立即使旧 key 失效 |
| `GET /admin/api/keys/{id}/usage` | 该 key 的近期汇总 |

当前单项路由只支持更新/删除，非敏感详情由列表提供；需要独立详情页时再增加单项 GET，避免文档宣称不存在的接口。

明确限制的语义，避免前后端各自解释：

- 更新时字段缺省表示保留；`rpm/expiresAt: null` 表示清除；IP/模型列表使用 `[]` 清除。若同时支持列表 `null`，必须补解码逻辑与契约测试。
- 空 IP/模型列表表示不额外限制。限制模型的 key 必须拒绝无法解析/缺失模型的推理请求，避免落入上游默认模型。
- key 的 RPM 是滚动 60 秒内获准的推理请求数；模型列表查询、格式错误、权限拒绝不消费推理 RPM。上游失败是否计数采用“已准入即计数”。
- `GET /v1/models` 需要鉴权和 IP/过期校验，但不得因查询列表消费推理 RPM。实现已分离 `Validate` 与推理 `Authorize`，列表按相同模型策略过滤并有回归测试。
- 只有受信代理的 `X-Forwarded-For` 才参与 IP 解析，并从最近一跳向前找第一个不受信地址；无效链回退 socket 地址。
- `Authorization: Bearer` 与 `X-API-Key` 同时存在时保持明确优先级，并测试错误 Bearer 不会悄悄改用其他身份。
- 管理登录 cookie/管理令牌与推理 key 分离；推理 key 不能访问管理 API。
- 既有静态兼容 key 在界面标明来源与“不受托管 key 单独限制”。全局模型/容量限制仍作用于它；匿名访问只在显式配置时启用。

### 前端

延续现有后台样式：桌面表格、移动端条目、创建/编辑对话框、轮换/删除确认。列表同时展示状态、过期时间、限制、最近使用与请求量；提供按 key 跳转请求记录。

模型使用多选，IP 使用多行输入，RPM 使用数字输入，启停使用开关/复选框。对话框关闭、登出和 session 失效时同步清除 secret；迟到的异步响应不得重新展示 secret。409 后刷新数据并保留错误反馈。

### 验收

覆盖创建、清除限制、启停、过期、IP/CIDR、代理伪造、模型拒绝、RPM、轮换并发、删除、持久化重启，以及管理接口的 cookie/跨站校验。浏览器覆盖复制、关闭/登出清理、版本冲突、网络失败和多尺寸布局。

## 4. P1：统一身份和审计，避免请求路径同步写全量文件

实现已增加 key ID/名称、客户端 IP、request ID、授权结果和按 key 筛选。生产入口使用 `usage.NewControl`：started/completed 使用同一个 request ID，经有界队列批量写入 SQLite，查询可见存储降级。历史导入采用事务，恢复使用owner心跳，查询读取共享快照，错误与参数采用结构化脱敏。旧 `NewPersistent` 仍保留同步 JSON 路径用于兼容，不能把两条路径的保证混为一谈。幂等保留期边界、升级前WAL快照和响应写出panic失败记录已补回归。

后端分开处理请求事实、聚合和明细持久化：

1. 请求进入时建立 started 事件，记录根 request ID；鉴权拒绝也有结束事件。完成事件更新同一个请求，不重复增加请求总数。
2. 每次上游尝试记录 attempt ID、账号 ID、上游模型、状态和耗时；客户端只看到一个请求结果。
3. 内存聚合使用短锁更新，明细经有界队列批量入库。队列满时不阻塞推理，增加 dropped 计数；不能静默吞错，也不能依靠无限 goroutine 积压。
4. 查询接口暴露队列长度、丢弃数、最近持久化成功/失败时间、降级状态。审计失败不改变已经完成的上游响应。
5. 保留 7 天/50,000 条等现有限制作为兼容基线；长期聚合独立于明细淘汰。重启后将未结束请求标记为 interrupted，不能当成成功。
6. 错误正文、参数与 prompt 按白名单/限长/脱敏处理，不能直接将上游错误正文截断后当作安全日志。现有图像 prompt 保留行为单独列入数据清单。

前端在请求记录增加进行中/中断状态、key 筛选和尝试详情；在存储异常时显示降级时间和丢弃数。24 小时 key 汇总标明统计窗口与明细保留范围。

验收包括队列满、慢磁盘/不可写、优雅退出 flush、进程中断、长流中途取消、鉴权拒绝及清理明细后聚合保留。需要基准数据才能声称请求延迟得到改善。

## 5. P2：模型目录、权限、别名和冷却共用策略

### 目录与权限

模型目录至少区分上游 ID、公开 ID、启用状态、别名、能力、价格来源与更新时间。能力只声明经过上游确认的 endpoint/input/output/stream 支持，未知值保留 unknown。

已实现 `internal/modelpolicy`，请求开始取得一个策略 revision 的快照；使用相同逻辑处理管理界面的有效状态、公开 `/v1/models` 和推理授权：

`全局模型启用 ∩ key 模型白名单 ∩ 当前 endpoint 能力 ∩ 可用上游候选`

全局禁用不能被 key 白名单覆盖。key 权限匹配稳定的策略 source ID；客户端提交公开 ID 后先解析到 source ID，再校验权限，最后选择上游模型。这样别名不能绕过限制，改名也不会悄悄扩大授权。

别名写入需要验证重复、与原名冲突、悬空目标、循环映射及 endpoint 不兼容。JSON 请求通过结构化解析替换 `model`；multipart 重建字段，不做原始字节替换。响应中的公开模型名按协议需要映射，避免泄露或混淆上游名称。

工作树已实现列表 `GET /admin/api/model-policies` 与单项 `PUT/DELETE /admin/api/model-policies/{source}`；写入带 revision，冲突返回 409。单项详情由列表提供，没有单项GET接口。

### 冷却

复用 `internal/upstream/upstream.go` 的账号池与现有账号禁用/积分冷却。新增 `(accountID, upstreamModel)` 粒度的 429 冷却，保存原因、最近错误、触发时间、恢复时间，合理裁剪异常 `Retry-After`。

模型 429 不影响该账号其他模型；明确账号级封禁才影响整个账号。冷却是可恢复的暂态，不能伪装为人工禁用。持久化失败保留内存保护并报告降级；恢复的截止时间有最大上限。

### 前端与验收

扩展现有模型列表，提供启停、公开名称、上游映射、能力与价格来源，展示规则 revision。key 编辑器使用同一个目录，并显示“有效允许模型”；账号页列出模型冷却原因及恢复时间。

测试列表可见性与实际调用一致、别名无法绕过白名单、停用立即生效、映射/并发冲突、不同账号同模型隔离、不同模型冷却隔离，以及重启恢复。

## 6. P3：容量、预算、可靠性、作业和缓存

### 6.1 准入和资源释放

新增 `internal/admission`，区分全局、key、模型、账号四个层次的并发限制。现有 `auth.rpm`/`rpmInFlight` 实际表示账号并发，前端已经称为“每账号并发上限”；保留配置兼容性，新增字段与接口采用 `maxConcurrent`，不要与 key RPM 混为一谈。

请求顺序建议为：

`生成 request ID → 头部鉴权/IP → 方法校验 → 全局/key 容量与读体预算 → 有界解析 → 模型策略 → RPM/配额/模型容量原子准入 → 上游尝试 → 最终结算与释放`

模型等后置准入失败时释放已占用的前置资源。过载尽早拒绝，不排无限队列。所有租约使用幂等释放，覆盖返回、panic、客户端断开、超时和重试的每条路径。

请求体限制保留现有 chat/JSON/multipart 分类型上限，再增加全局在途字节预算、读取截止时间和临时文件清理。`Content-Length` 只作提前判断，对 chunked 请求同样按实际读取字节限制。

超时分为连接/响应头、首个有效响应字节、流空闲、整体时长。图片任务单独配置较长整体时长；不能把首字节超时误用为整个流时长。客户端取消必须终止上游请求并释放账号槽位。

key RPM/配额超限返回 429；全局容量耗尽或无可用账号返回 503；请求体过大返回 413；超时在尚未输出时返回 504，并按可计算值提供 `Retry-After`。

### 6.2 请求、token、积分配额

这是扩展设计。配额至少区分日/月、key 和计量单位，并在保存时明确时区；推荐沿用配置时区，不能从浏览器时区推导账期。

以 request ID 作幂等键，在同一事务中检查 `已用 + 已预留 + 本次预留 <= 上限`。先预留再调用上游；完成后结算实际用量并释放差额。限额修改有 revision，不能通过重试重复结算。

- 请求数按成功准入计数；拒绝、格式错误和模型列表不计费。一次客户端请求的故障切换不重复增加请求数。
- token 取非流响应 `usage` 或流结束 usage，不能通过字节数伪造精确 token；输入估算与计费值分开保存来源。
- 积分使用可信上游/本地计费记录，并保持定点整数。余额差无法在并发下准确归因给某个 key，不能作为精确结算依据。
- 配置硬 token/积分限额时，必须能计算保守预留上界。无可信上界/计量来源的模型明确拒绝该受限调用；不能将 unknown 按 0 继续放行。
- 流中断或进程崩溃后的未知费用保留未决预留，经过对账再释放；已发送请求不能因为客户端取消就假定没有产生费用。

前端在 key 编辑增加并发及日/月配额，列表展示已用、预留、剩余、重置时间和计量来源。请求数、token、积分分别展示，不换算成未经核实的金额。

v0.3.0已落地上述状态机：模型编辑可声明 `upstream-usage-v1` 和整数单请求上界，Key编辑设置日/月Token与积分上限。只有最终上游模型的契约生效；受限调用最多尝试一次。JSON或最终SSE usage对象中的 `total_tokens/credits` 用于结算，部分已知维度立即结算，其余维度保留预留；设置页按版本提交实际用量对账。已知用量超过上界会封锁该key活跃账期内的后续受限调用，包括部分结算。

契约和上界需要管理员结合实际协议核实，界面勾选不能自动证明正确。上游将不同维度拆分为多个usage事件、缺少结束usage、非整数积分或其他账单协议均不保证自动结算；未知预留必须经过可信对账。未实现对账操作的独立财务审计日志，不能将其作为财务系统。

### 6.3 重试和切换

保留当前安全失败切换并增加尝试次数/总时间预算；已经输出响应头或正文后，不切换账号拼接结果。图像生成/编辑涉及重复扣费，不扩大现有重试范围，只有明确未提交的失败才允许重试。

审计区分准入拒绝、登录失败、上游限流、首字节超时、客户端取消和流中断。每次重试共享一个客户端配额预留，账号租约逐次获取/释放。

### 6.4 可观察后台任务

建议新建 `internal/jobs`，将批量签到、兑换、刷新、探测改为服务端作业。创建接口返回 202 和 job ID；UI 关闭/重新加载不取消任务，用户主动取消才调用取消接口。

工作树已实现 `POST/GET /admin/api/jobs`、`GET /admin/api/jobs/{id}`、`POST /admin/api/jobs/{id}/cancel` 与 `/retry`。状态为 `queued/running/succeeded/partial/failed/cancelled/interrupted`，结果包含逐账号步骤、进度和安全错误信息。当前probe仅验证指定账号登录和模型列表连接，不发送计费推理请求。

按任务类型与目标集合计算幂等键，重复触发返回已有运行任务。有界队列/工作池限制任务数量；重试仅重做可安全重试的失败项。兑换是否支持幂等必须由上游行为验证，不能自动重发结果未知的兑换。

作业状态持久化后，重启将运行任务标记 interrupted；仅经过验证的幂等任务可自动恢复。定时任务与手动任务共用去重规则，跨进程使用持久化租约。

前端提供可恢复的进度区、逐项结果、取消、重试失败项。仅在存在运行任务时轮询；登出清理计时器，旧请求响应不得污染新 session。

### 6.5 缓存

实现复用 1 小时 TTL、stale 返回和后台刷新，持久化改为SQLite。同一资源并发刷新已合并为一个共享任务；取消等待方不会取消共享刷新，失败账号保留旧积分快照。

API 返回 `cacheState/cachedAt/age/refreshing/lastError/partialFailures`；前端区分命中、过期数据、刷新失败回退、部分账号失败。空列表不等于全部成功，不应覆盖最后一个有效完整快照。

### 验收

并发场景验证租约只释放一次、取消不泄漏、重复创建作业不重复执行、配额不能并发穿透、重启不清零账期计数、流结束/中断用量结算、首次输出后禁止切换，以及刷新合并与部分失败。

## 7. P4：控制数据、配置、迁移与备份

### 7.1 仓储和 SQLite

已实现 `internal/controlstore`，将 key、模型策略、设置覆盖、会话摘要、冷却、作业、配额与审计聚合移到明确的仓储边界。路由和 UI 不依赖 SQL；身份有摘要索引，存储快照按revision刷新。

实现使用纯 Go SQLite 驱动 `modernc.org/sqlite v1.38.2`。本机 Android全量测试通过，完整程序的Linux amd64/arm64/armv7、Windows amd64和Android arm64 PIE均已在CGO关闭下交叉构建。Go1.23最低工具链和Linux race仍须由远端CI验证；交叉构建不等于在每个目标系统上运行通过。

事务使用短写入、busy timeout、外键和明确迁移版本；写操作通过 `WHERE version/revision = ?` 比较更新并检查影响行数。变更事务提交后再发布内存快照，提交失败不让运行态领先持久态。

当前控制数据和审计使用同一数据库，审计经有界批次写入；独立审计数据库留作有实际负载证据后的优化。会话仅保存随机 token 的摘要和到期时间；管理令牌不转存到普通配置返回值。

同机多进程不能只“共享一个 SQLite 文件”就宣称共享限流：RPM、配额预留、并发租约和任务 owner 都必须进入事务/租约表；实例按 revision 失效内存缓存。租约需要 owner、到期与心跳。SQLite 不承担跨主机分布式存储，不支持直接挂网络文件系统扩展实例。

### 7.2 配置生效规则

工作树已采用 CLI > 环境变量 > 管理覆盖 > 文件 > 默认值。核对发现原 `lfhy/flag` 的 `ConfigVar` 不会自动注册环境变量，因此显式增加 `CLODESEN2API_SECTION_KEY` 读取，例如 `CLODESEN2API_AUTH_RPM`、`CLODESEN2API_UPSTREAM_BASE_URL`；原库注释不能视为运行行为。

管理覆盖保存为SQLite文档，不回写合并后的配置到TOML。账号策略/并发、签到启停/时间、自动兑换、更新源即时生效；监听、上游连接、API鉴权来源/路径等重启生效。上游session保持启动配置不可变，避免并发请求读到部分更新配置。

配置读取响应返回 revision、有效值、存储值、来源、locked 和 `hot/restart` 生效模式。敏感值只返回是否已配置；CLI/环境变量锁定字段在后端拒绝覆盖，前端同步只读。

保存采用“复制候选 → 完整校验 → 事务保存 → 发布快照/安全重建运行资源”。仅热更新字段立即生效；监听地址、数据路径等需要重启的字段显示 pending 状态，不能一律返回 `restartRequired: true` 掩盖实际行为。

### 7.3 迁移与恢复

首次导入以每个仓储为事务边界，记录来源指纹/迁移标记；重复启动不重复导入，旧TOML/JSON原件保留。SQLite schema升级前另存WAL一致性快照。当前没有额外生成旧目录的跨文件一致性归档；升级前需要完整保留旧数据目录。未知新schema拒绝启动，损坏数据不覆盖原件。

校验导入前后 key/账号数量、摘要、过期时间、模型限制、统计合计和配置有效值。迁移成功后原文件保留为只读回滚材料，避免同时写 JSON 和 SQLite 形成双主。

备份采用在线一致性快照或暂停写入后的 checkpoint，不能只复制 WAL 模式下的主文件。清单包含应用版本、schema、相对文件名、哈希、大小和是否包含敏感数据。

本次实现只提供“完整恢复备份”，不提供容易混淆范围的脱敏控制备份。数据库、TOML与管理令牌均可能含凭据，下载由已登录管理会话授权并设 no-store/受限文件权限。

恢复分两步：先上传到受限暂存区并验证文件白名单/哈希/schema/数据库完整性/路径穿越，再生成恢复计划；执行前再备份当前状态，停止接收新任务并等待或终止在途操作，原子替换后重启验证。备份创建成功不等于恢复验证成功。

已接生产入口并补真实双进程演练：其他实例未停时返回409，独占成功后返回202并排空HTTP/worker/审计，关闭数据库后重启，在启动前再次校验并替换。替换失败回滚原文件；替换成功后若应用启动仍失败，需要管理员从恢复前备份手工恢复。保护范围是当前控制数据和配置，不包含程序二进制、操作系统或CLI/环境变量。

前端扩展设置/存储区域，展示数据类别、大小、保留期、备份范围、验证结果和恢复状态。更新前自动备份，定时只清理超过保留数的自动备份。

### 9.1 前后端共同完成标准

每个模块按“后端契约 → Go 实现/测试 → 静态 JS 状态与交互 → 浏览器联调 → 失败/重启验证”交付，不能只提供管理接口或只提供一个可点击页面。

| 模块 | 前端必须出现的状态 | 后端必须证明的约束 |
| --- | --- | --- |
| key | 空列表、保存中、过期、停用、冲突、一次 secret、session 失效 | 读体前拒绝、原子轮换、限制清除、无明文泄漏 |
| 模型 | 启停、公开/上游名称、能力未知、有效权限、冷却时间 | 列表与调用一致、稳定 source ID 授权、禁用不可绕过 |
| 审计 | 进行中、完成、中断、存储降级、筛选及分页 | 一次客户端请求一条主记录、开始/结束幂等、保留期独立于聚合 |
| 作业 | 排队/进度/部分失败、取消、重载续查 | 有界队列、重复触发去重、取消释放、未知结果不自动重发 |
| 配置 | 来源、锁定、冲突、待重启及保存失败 | 候选校验、事务提交后生效、外部锁定不可覆盖 |
| 备份 | 备份范围、下载、校验结果、恢复计划和恢复后状态 | WAL 一致性、文件白名单、哈希/schema 校验、实际恢复启动 |
